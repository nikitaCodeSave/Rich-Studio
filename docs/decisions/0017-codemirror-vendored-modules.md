# 0017. Подсветка и подсказки в исходнике: CodeMirror 6 модулями из npm, без сборщика

2026-11-15, задача #96: три прототипа (A, B, C), выбор Никиты «вариант A».

**Решение.** Вкладки HTML, Markdown и JSON получают CodeMirror 6: подсветку, подсказки из спецификации, поиск и замену, скобки, отмену. Пакеты лежат в `app/static/vendor/codemirror-<хеш>/` так, как их публикует npm: ES-модуль каждого пакета (`dist/index.js`) побайтно, только bare-импорты (`'@codemirror/state'`) переписаны в относительные (`'./state.js'`) и сверху одна строка-заголовок. Это делает `scripts/vendor_codemirror.mjs` без зависимостей. От корневых пакетов (`ROOTS` в скрипте) он идёт по импортам и падает на `import()`, на относительном импорте внутри пакета, на импорте, который не смог переписать, на второй версии пакета в `package-lock.json` и на лицензии не MIT. Рядом с файлами он пишет `manifest.json` (версии, sha256, кто что импортирует) и сводный `LICENSE`. Редактор импортирует один сгенерированный модуль `app/static/vendor/codemirror.js`, в нём корневые пакеты стоят пространствами имён (`cm.view.EditorView`). Типы для `tsc` лежат в `codemirror.d.ts` и берутся из тех же версий в `node_modules`: опечатка в имени из CodeMirror ловится как ошибка типов. Все пакеты набора, включая транзитивные, записаны в devDependencies с точными версиями. Node нужен только скрипту и `tsc`, образ собирается без него.

**Сравнение.**

| | A: CM6 модулями | B: CM6 бандлом esbuild | C: своё на textarea |
|---|---|---|---|
| Сборщик | нет ([0001](0001-no-bundler.md) цел) | нужно исключение из 0001 | нет |
| gzip при первом открытии | 290–380 КБ (лениво) | 207 КБ | 16 КБ |
| Дифф обновления | читаемый, файлы побайтно как в npm | 600 КБ минифицированного | — |
| Свой код | ~0,5 тыс. строк | ~0,5 тыс. строк | 1,1–1,3 тыс. строк движка |
| Возможности | всё из коробки (поиск/замена, скобки, undo) | то же | без замены и скобок |
| Риск | сторонние IME на телефоне | то же + сборщик | наложение подсветки, медленно в WebKit на больших постах |

**Почему не бандл (B).** Бандл экономит около 150 КБ gzip на редакторе, который и так грузится лениво. Ради этого пришлось бы делать исключение из 0001 и коммитить минифицированный файл, дифф которого при обновлении не прочитать. Копия по файлам не нарушает 0001: сборки нет, браузер грузит модули как есть, скрипт только копирует и переписывает строки импорта.

**Почему не своё (C).** Свой движок на трюке с наложением подсветки поверх textarea даёт больше своего кода (больше тысячи строк) и меньше возможностей: нет замены и парных скобок, подсветка расходится с текстом, на больших постах WebKit работает медленно.

**Почему каталог с хешем и один модуль.** `StaticFiles` отдаёт файлы без `Cache-Control`, и браузер кэширует их по своей эвристике. С одним и тем же адресом после обновления часть файлов пришла бы из кэша старой версии, и на странице смешались бы версии: новый `view.js` встретился бы со старым `state.js`. Имя каталога — хеш содержимого, поэтому у нового набора новые адреса. Студия отдаёт `codemirror-<хеш>/` с `Cache-Control: immutable` на год, а сам `codemirror.js` с `no-cache`: браузер перепроверяет его при каждой загрузке и не уходит по старой ссылке в удалённый каталог (`app/main.py`). Путь с хешем меняется при каждом обновлении, поэтому знает его только `codemirror.js`, и в коде редактора его искать не надо. Этот модуль заодно запрашивает все файлы набора сразу: иначе браузер шёл бы по уровням импортов, до девяти запросов подряд (`lang-markdown` → `lang-html` → … → `state`). Import map не подходит: inline-карту запрещает наш CSP, а внешнюю (`<script type="importmap" src>`) браузеры не поддерживают.

**Цена.**
- Вес: 24 файла, 1,4 МБ (gzip около 380 КБ). Они грузятся при первом открытии вкладки исходника, а не вместе со страницей, и дальше берутся из кэша. Весь набор приходит сразу, даже когда открыт только JSON: разница около 90 КБ gzip не окупает второй способ загрузки. `lang-html` тянет разбор CSS и JavaScript для `<style>` и `<script>`, это 135 КБ без сжатия (51 КБ gzip), которые разметке Telegram не нужны. Вырезать их значит править файлы пакета, а этого мы не делаем.
- Частые обновления: `@codemirror/view` выходит почти каждую неделю, и после каждого PR Dependabot нужен `make vendor`.
- Мобильные IME: CodeMirror сам обрабатывает ввод в contenteditable, и сторонние экранные клавиатуры на телефоне могут сбоить. Поэтому значение по-прежнему хранит textarea, а у редактора будет переключатель «простой редактор», который запоминается.

**Как обновлять.** `make vendor-update` поднимает все пакеты набора до последних версий (точно, в `package.json` и `package-lock.json`) и собирает каталог заново. Пакет, который новые версии добавили или убрали, скрипт сам добавляет в devDependencies или убирает оттуда. PR Dependabot по CodeMirror идёт отдельной группой `codemirror` (`.github/dependabot.yml`), не в еженедельной `js`, и меняет только `package.json` и lock. Поэтому в его ветке надо выполнить `npm ci && make vendor` и запушить результат, как `make lock` для pip (`.claude/skills/ci-triage/SKILL.md`). `make check` и CI сверяют каталог с lock побайтно (`--check`, лишний файл — тоже ошибка). `npm run test:codemirror` загружает набор в Node и отказывает каждому bare-импорту, так что конец проверки за парсером V8, а не за регулярными выражениями скрипта. Новый пакет в наборе добавляется строкой в `ROOTS`.

**Отказались.** От бандла (B) и своего редактора (C), см. выше. От CDN: студия работает без интернета, а CSP пускает только свои скрипты. От минификации: без сборщика её не сделать, и дифф перестал бы читаться, а gzip сокращает разницу. От `.d.ts` на каждый файл набора: редактор импортирует только `codemirror.js`.

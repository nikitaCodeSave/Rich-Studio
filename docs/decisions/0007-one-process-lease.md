# 0007. Один процесс с lease в SQLite

2026-10-28, ревью к продакшну (этап 3), Никита выбрал «свой сервер».

**Решение.** Студия работает одним процессом. Фоновые циклы (планировщик, getUpdates, восстановление постов, застрявших в `sending`) запускаются только под lease в таблице `meta`, который процесс продлевает каждые 20 секунд и который истекает через 60. Второй процесс (лишний воркер, новый контейнер раньше остановки старого) отвечает на HTTP, но циклы не ведёт, пока lease держит первый. SQLite в режиме WAL.

**Почему.** Планировщик, `in_flight`, восстановление после падения и getUpdates рассчитаны на один процесс. Без защиты второй процесс при старте пометил бы «мог уйти» посты, которые честно отправляет первый, а getUpdates допускает одного потребителя на бота (второй получает 409). Для одного канала и нескольких агентов одного процесса хватает с большим запасом, а lease — это одна строка в таблице и около сотни строк кода.

**Отказались.** От нескольких воркеров и реплик с очередью отправки и Postgres: это нужно только сервису для многих авторов (сценарий Б в ревью), а здесь только добавит движущихся частей. От async-драйвера SQLite: WAL убирает ожидание читателей, запросы короткие.

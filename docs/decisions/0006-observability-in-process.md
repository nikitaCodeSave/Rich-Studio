# 0006. Наблюдаемость внутри процесса, без внешнего стека

2026-10-09.

**Решение.** Журнал JSON с ротацией в `DATA_DIR/logs`, отчёт о состоянии `GET /api/health`, счётчики в памяти процесса и самоконтроль фоновым циклом. Агент читает всё это через API или MCP. Подробности: [OBSERVABILITY.md](../OBSERVABILITY.md).

**Почему.** Студия — один контейнер на одном компьютере для одного человека. Prometheus, Loki, Grafana, OpenTelemetry Collector или Sentry добавили бы 2–4 контейнера с настройкой, обновлениями и местом на диске, то есть больше движущихся частей, чем в самой студии. Главный потребитель — агент в Claude Code: ему нужен ответ «что сломано и что делать» в одном JSON, а не графики. Ротация из стандартной библиотеки (`RotatingFileHandler`) обходится без новой рантайм-зависимости вроде structlog или loguru.

**От чего отказались.**
- Prometheus `/metrics` + Grafana: нужны, когда сервисов много и важны тренды. Если внешний мониторинг появится, `/metrics` делается поверх `metrics.py` (этап 2 в OBSERVABILITY.md).
- Loki / ELK: журнал до 20 МБ фильтр `/api/logs` читает за доли секунды.
- Sentry: отправляет трассировки на внешний сервер; для личного инструмента с токеном бота это лишний риск.
- Счётчики в SQLite: запись на каждый запрос, а после перезапуска история и так есть в журнале.
- Автоудаление сделанного человеком по умолчанию: версии постов и загрузки удаляются только по `VERSIONS_KEEP` и `MEDIA_UNUSED_DAYS`, иначе отчёт показывает рост, а решает человек.

# 0008. Общие списки как отдельные файлы и сгенерированные справочники

2026-10-28, ревью к продакшну (этап 2): над репозиторием параллельно работают несколько агентов.

**Решение.** То, что почти каждый PR дописывал в один и тот же список, разнесено по файлам. Шаг схемы — это файл `app/store/migrations/NNNN_имя.sql`. Инструмент MCP живёт в модуле `app/mcp_tools/tools/<область>.py` с `register(tool)`, и `server.build()` подхватывает модули сам. Браузерная проверка — файл `tests/e2e/NN-имя.mjs`. Списки маршрутов HTTP и инструментов MCP не пишутся руками: `make docs` собирает их в `docs/reference/` из `summary=` и docstring маршрутов и docstring инструментов, тест сверяет их с кодом. README и SKILL.md на них ссылаются.

**Почему.** Два PR, которые дописывали строку в конец одного списка (`MIGRATIONS`, `EXPECTED_TOOLS`, таблица API в README, строка инструментов, `e2e_ui.mjs`, `server.py`), конфликтовали при каждом merge. Отдельный файл на элемент не конфликтует, а повтор номера миграции ловит тест. Сгенерированный список может конфликтовать, но такой конфликт не сливают руками, а снимают `make docs`. Описание живёт рядом с кодом, поэтому не расходится с ним.

**Отказались.** От merge driver `union` для README: он склеивает строки таблиц без проверки и может их задвоить. От разрешения конфликтов генерацией через `.gitattributes`: это нужно настраивать у каждого клона и агента, а `make docs` уже в правилах. От автонумерации миграций по времени: с номерами по порядку видно, что за чем идёт, а занятый номер сразу заметен.

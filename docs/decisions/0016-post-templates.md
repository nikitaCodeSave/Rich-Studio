# 0016. Шаблоны постов: поля `{{key}}` только там, где значение остаётся текстом

2026-11-15, задача #93: рубрику (дайджест, анонс) сохранить шаблоном с полями и получать из неё новый черновик в редакторе и через MCP. Идея взята из форка xarleyn/Rich-Studio, код написан заново.

**Решение.** Шаблон — отдельная таблица `post_templates(id, title, payload, fields, version, …)`, а не особый черновик. Поле — `{key, label, type: text | multiline | url, required, default}`. `{{key}}` стоит только в строковых значениях поста; в ключе JSON он не принимается. При заполнении значение всегда остаётся текстом: в HTML (`html` у `rich_message` и у первого комментария) его экранирует `html.escape`, в остальных строках оно уходит обычной строкой JSON (текст блока Telegram не разбирает). Поэтому при сохранении шаблона (422) проверяется, где стоит переменная. В HTML она допустима только в тексте и в значении атрибута в кавычках. Сырое `<` в HTML для Telegram всегда начало тега, так что переменная в имени тега или атрибута, в значении без кавычек и в комментарии отвергается. В `href`/`src` (и других атрибутах-ссылках из `render.js`) допустимо только поле типа `url`, и только целиком. Поле `url` принимает схемы, которые открывает предпросмотр (`http(s)`, `tg`, `mailto`, `tel`), или файл `upload:имя`. Переменная рядом с `parse_mode` или `entities` (подпись медиа, вопрос опроса) не принимается: Telegram разметил бы значение по ним. Ссылку `upload:` подставляет только поле целиком; если она собирается из частей при заполнении, это тоже 422. У шаблона есть `version`: правка, удаление и заполнение по старой версии получают 409. Заполнение создаёт новый черновик без каналов. Размер результата считается до того, как пост собран (на каждую подстановку прибавляется длина значения), и больше 1 МБ — 413. Остальное в посте не меняется (правило 1 AGENTS.md). Файлы из поста шаблона и из значений по умолчанию считаются нужными: уборка их не трогает, удаление спрашивает подтверждение. В редакторе шаблоны — свёрнутая строка над черновиками: четвёртая вкладка не помещается в боковую колонку 240 px. Строки, которые можно сделать полем, находит обход JSON поста, а не список типов блоков; пары «поле=значение», которые фиксирует спецификация (тип блока, значение enum), полем не предлагаются.

**Почему так.** Подстановка, которая экранирует значение по месту, закрывает класс ошибок «значение стало разметкой» целиком, если места проверены заранее, при сохранении шаблона. Отказ при сохранении понятнее, чем пост, который потом сломается или выйдет не таким. Размер считается заранее, потому что 1 МБ шаблона с полем, повторённым тысячи раз, иначе собрал бы гигабайты.

**Отказались.** От Markdown в v1: как экранировать значение для Markdown Telegram, ни с чем не сверено. Числовые сущности `&#NN;` из форка внутри кода и формул видны буквально, а свой сканер Markdown на Python пришлось бы держать в согласии с разбором Telegram. Поэтому переменная в Markdown — понятный отказ «переведите в визуальный режим или HTML». От шаблона как особого черновика или записи в localStorage: у него своя версия и свои поля, и агенту он нужен через API. От языка шаблонов с условиями и циклами: рубрике нужна подстановка строк, а логика в шаблоне усложнила бы проверку мест. От частичной подстановки в `upload:` и в ссылки (`https://site/{{slug}}`): файл или адрес, собранный из кусков, не видят ни уборка файлов, ни проверка схемы.

**Не сверено с Telegram.** Экранирование `html.escape` даёт `&lt;`, `&gt;`, `&amp;`, `&quot;` и `&#x27;`. По документации Bot API для HTML поддерживаются эти именованные сущности и все числовые. Примера с ними в `tests/telegram_parse/` пока нет.

# 0020. Dependabot только там, где его PR готов как пришёл

2026-11-15: с тех пор как появился `requirements.lock`, каждый PR группы `python` приходил красным, и в его ветку пушили наш коммит с lock (#73, #81, #138). Dependabot поднимает `requirements.txt`, а lock с хэшами, который ставит образ, собирает только `make lock`; после чужого коммита Dependabot перестаёт обновлять ветку. С группой `codemirror` то же самое: без `make vendor` она красная (0017). Python в образе Dependabot предлагал сменить с 3.12 на 3.15 (#136), хотя CI и lock собраны под 3.12.

**Решение.** Dependabot открывает только PR, которые зелёные без нашего коммита в их ветке, и человек их сливает как есть (`.github/dependabot.yml`):
- npm: инструменты разработки (eslint, typescript, playwright), одной группой раз в месяц; CodeMirror и всё, что он импортирует, исключено.
- docker: `python:3.12-slim` раз в месяц, только новый digest того же тега (в нём патчи Python и Debian); minor и major не предлагаются.
- docker-compose (`deploy/`: Caddy и Litestream): раз в неделю, без major; у Litestream (0.x) и без minor.
- github-actions: одной группой раз в месяц, major тоже: его проверяет тот же прогон CI.

Python-пакеты, CodeMirror, minor Python и major чего угодно обновляются намеренно. Python-пакет: поднять пин в `requirements.txt` или `requirements-dev.txt` и `make lock`; зависимости зависимостей к новым версиям поднимает `make lock LOCK_ARGS=--upgrade`, одну `make lock LOCK_ARGS="--upgrade-package <имя>"`. CodeMirror: `make vendor-update` (0017). Новый minor Python меняется вместе с `python-version` в CI и `--python-version` у `make lock`.

**Почему.** Безопасность от этого не зависит: свежую CVE ловит еженедельный прогон CI на `main` по расписанию (`pip-audit` по lock со всеми транзитивными пакетами, `npm audit` с CodeMirror, Trivy по образу), и ci-triage чинит её отдельным PR. Уведомления безопасности Dependabot в репозитории выключены. Чинить его PR нашим коммитом в его ветке значит каждую неделю делать руками его работу, а сам он после этого ветку не обновляет. Версии рантайма (FastAPI, pydantic, MCP) в личном инструменте лучше поднимать, когда есть причина и время прочитать changelog, а не по расписанию.

**Цена.** Python-пакеты без CVE стареют, пока их не поднимут руками. Отложенное обновление копится и потом приходит одним большим PR. Красный прогон по расписанию виден только письмом GitHub (его получает тот, кто последним менял `cron` в `ci.yml`) и в `gh run list --event schedule`; Trivy роняет сборку только на критической CVE, у которой есть исправление.

**Отказались.** От workflow, который сам пушит lock в ветку Dependabot: push с `GITHUB_TOKEN` не запускает CI, и PR остался бы без проверок; кроме того, это токен с правом записи, который выполняет резолвер на входе от бота. От перехода на `uv.lock` (у Dependabot есть экосистема `uv`): меняются образ, CI, `pip-audit --require-hashes` и `tests/test_lock.py`, и ради одного бота это не окупается. От полного удаления Dependabot: для Caddy на сервере, digest базового образа и actions его PR приходят зелёными, а других уведомлений о новых версиях у них нет.

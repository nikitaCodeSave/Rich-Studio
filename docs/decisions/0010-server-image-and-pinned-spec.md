# 0010. Сервер: свой образ из GHCR, закреплённая спецификация, Caddy и Litestream

2026-10-28, ревью к продакшну (этап 5), сценарий «свой сервер». Частично пересматривает [0003](0003-spec-source.md).

**Решение.**
- Образ собирает CI (`.github/workflows/image.yml`) и кладёт в GHCR: `:main`, `:<sha>`, `:<версия>` по тегу `v*`, для amd64 и arm64, с SBOM и provenance от buildx (attestations GitHub в приватном репозитории требуют Enterprise Cloud, без них). Локальный compose запускает тот же образ от пользователя хоста, чтобы `./data` оставалась его. База закреплена по digest, пакеты ставятся из `requirements.lock` с хэшами (`make lock`, `uv pip compile`). Процесс работает от uid 10001.
- `STUDIO_MODE=server` (его ставит `deploy/docker-compose.yml`): без токена или ключа, без `https://` в `STUDIO_URL` и без токена бота студия не запускается и говорит, чего не хватает. Все настройки проверяются при старте, ошибки перечисляются разом. Секреты читаются из файлов (`TG_BOT_TOKEN_FILE`, `STUDIO_API_KEY_FILE`).
- На сервере спецификация закреплена (`SPEC_PIN`, по умолчанию включён в серверном режиме): студия работает на `app/bundled/api.json` из образа и ничего не скачивает. Новая версия Bot API приходит как обычно: `make spec-update` → PR → CI → новый образ. Локально всё как в 0003: скачивание при запуске, раз в 12 часов и по ↻.
- Снаружи только Caddy (HTTPS от Let's Encrypt сам). Litestream непрерывно копирует `studio.db` в S3. Все три контейнера read-only, без capabilities, с лимитами памяти. Восстановление из реплики проверяет CI каждый день (`scripts/restore_check.sh`).

**Почему.** На сервере скачивание чужого `main` в рантайме — это код, который никто не видел, в процессе с токеном бота; закрепление делает проверку целостности ненужной: что прошло тесты, то и работает. Проверка настроек при старте дешевле, чем разбор полуработающего сервиса. Litestream даёт потерю данных в секунды, а не сутки, как ежедневная копия, и не требует второго процесса БД. Caddy проще nginx + certbot: один файл, сертификаты сам. Проверка восстановления в CI ловит то, что бэкап, который ни разу не восстанавливали, обычно не работает.

**Отказались.** От подписи или хэша скачиваемой спецификации: при закреплении скачивания нет. От Postgres, Kubernetes и нескольких реплик ([0007](0007-one-process-lease.md)). От nginx и Traefik. От Tailscale и Cloudflare Access как обязательной части: это хороший слой поверх, но токены (0009) достаточны для одного человека, а лишняя зависимость от внешнего сервиса усложняет вход агентам. От копирования загрузок Litestream'ом: он умеет только SQLite, файлы есть в zip-бэкапе (`GET /api/export`).

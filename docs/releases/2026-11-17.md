## Changelog для поста

**Новое**
- Bot API 10.4 с первого дня: новая спецификация, адрес TON в редакторе и предпросмотре.
- Личный rich-ответ на нажатие кнопки под постом: его видит только нажавший, можно показать вместо поста.
- Шаблоны постов с полями `{{…}}`: в редакторе, через API и MCP.
- Пост, пересланный боту, становится черновиком с тем же оформлением.
- Редактор кода во вкладках HTML, Markdown и JSON: подсветка, поиск, подсказки тегов и полей из спецификации Bot API.
- Кнопка «В HTML» переводит визуальный пост в rich HTML. Если что-то не переводится, студия скажет, что и где, и ничего не потеряет молча.
- Агенты получают инструкцию по постам прямо из студии по MCP, без репозитория.
- Справочник API `/docs` работает без внешних CDN.
- Светлая и тёмная тема студии; выбор темы форума — в «Параметрах отправки».

**Проверка до отправки**
- Официальные лимиты rich-сообщений: длина, число блоков, 20 колонок в таблице.
- Длинный пост больше не уходит молча обрезанным: Telegram режет текст после ~35 000 байт, студия предупреждает заранее (замерено на настоящем Telegram).
- Предупреждения о том, что не сработает в выбранном чате: канале, группе, форуме.
- Поле не на своём месте — предупреждение, канал внутри поста — ошибка.
- Неверный опрос после поста виден сразу, а не при публикации.
- Число вне диапазона из спецификации (размер заголовка 1–6, масштаб карты 0–24) — предупреждение, а поле редактора обводит его красным.

**Предпросмотр как в Telegram Desktop**
- Адрес TON, код-блок, GIF, слайдшоу с подписью и листанием мышью и стрелками.
- Глубоко вложенные формулы, спойлер в спойлере, цвет кнопок.
- «Копировать» у кода берёт только видимый текст.

**Надёжность публикации**
- Если пост ушёл, а студия не смогла его записать, ответ говорит «не публикуйте повторно» и даёт номер сообщения.
- Пост с неизвестным исходом («мог уйти») помечен отдельно, у него свой фильтр, а защита от дубля не истекает.
- Планировщик не отправит пост, который перенесли или отменили в последний момент.
- При рассылке в несколько каналов сбой во втором не публикует дубль в первом.
- Опрос после поста и первый комментарий записываются до отправки и не теряются при обрыве.
- Редактор не теряет неприменённый JSON, ответы кнопок и незнакомые поля поста.
- Тема форума остаётся у своего канала после отмены, повтора и правки JSON.
- Проверка здоровья видит пропущенный после простоя пост, истёкший первый комментарий и проблемные версии SQLite.

**Безопасность**
- Токены и ключи маскируются в ответах API, ошибках и MCP.
- Студия на сервере не запускается с ключом короче 32 символов.
- Запросы к API с чужих сайтов отклоняются, в том числе на чтение.
- Файлы поста — только по имени из загрузок; предпросмотр берёт файлы студии только из `/media/`.
- Проверка и предпросмотр не зависают на враждебном вводе: время растёт линейно.
- Закрыта CVE в opentelemetry-api; образ проверяет Trivy, временное исключение CVE отключается само в назначенный день.

**Под капотом**
- Разработку ведут параллельные агенты в отдельных копиях репозитория (git worktree); ревью каждого PR делает не автор, слияние только на зелёном CI.
- CI запускает образ без сети и проверяет мягкую остановку и сохранность данных после перезапуска.
- Документация описывает только текущее состояние: README вдвое короче, отдельный тест ловит следы истории.
- Обновлены Litestream, Caddy, образ Python и зависимости.

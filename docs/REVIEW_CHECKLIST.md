# Чек-лист ревью Rich Studio

Ревьюер проходит его на каждом PR. Пункт «не применимо» — нормально, пропуск без причины — нет.

## 1. Правила AGENTS.md
- [ ] Дифф не нарушает «Главные правила» (1–6) и «Не делать» из `AGENTS.md`; ниже только то, чего там нет.

## 2. Нельзя опубликовать не туда и нельзя опубликовать дважды
- [ ] Адрес отправки явный: удалённый черновик, пустой элемент списка каналов или предпросмотр без `TG_PREVIEW_CHAT` — ошибка, а не канал по умолчанию.
- [ ] Новый путь отправки пишет строку `sending` до запроса и держит id в `publisher.in_flight`, как `publisher.publish`: падение посреди запроса оставляет «мог уйти», а не пустоту.
- [ ] Telegram принял — запись `sent`; база не приняла — `Unrecorded` с `message_id`, а не «не отправлено». Сбой шагов после записи (закреп, комментарий, опрос) — предупреждение, не `failed`.
- [ ] В рассылке после первого ушедшего (или «мог уйти») канала отказ в следующем — его `ok: false`, а не ошибка запроса: 4xx освободил бы `Idempotency-Key`, и повтор продублировал бы пост.

## 3. Ошибки
- [ ] Ошибки — классы из `app/errors.py`, и в слое API тоже, а не `HTTPException`: их одинаково понимают API, MCP и фоновые циклы.
- [ ] Ошибка пользователя — 4xx с русским текстом о том, что исправить.
- [ ] `except Exception` не теряет исключение: оно в журнале, в поле `error` или в ответе; у `# noqa: BLE001` есть причина.
- [ ] Круг фонового цикла ловит своё исключение и отдаёт его в `metrics.beat`: цикл не умирает, проверка `loops` видит ошибку.

## 4. Безопасность
- [ ] Пути без ключа (`security.PUBLIC_PATHS` и исключения в `security.guard`) расширены только намеренно. Уровень маршрута и инструмента MCP — как в «Куда добавлять новое» `docs/ARCHITECTURE.md`, с тестом в `tests/test_access.py`.
- [ ] Имя файла из запроса или поста проверяет `telegram.uploads.find` (удаление — `uploads.name_error`), а не своя проверка пути.
- [ ] Текст ошибки, который студия хранит, отдаёт или пишет в журнал, проходит `redact.scrub` или путь, который уже чистит (транспорт, `store`, обработчики ошибок, журнал). В тестах и коммитах нет настоящего токена.
- [ ] Правка `SAFE_PREFIXES` и `SAFE_METHODS` в `app/api/raw.py` не пропускает без `X-Confirm: yes` метод, который удаляет, банит или меняет настройки бота или канала.
- [ ] SQL только с параметрами `?`, имена колонок из белого списка (`store.posts.UPDATABLE`); у `# noqa: S608` есть причина.

## 5. Данные
- [ ] Схема меняется новым файлом миграции («Куда добавлять новое» `docs/ARCHITECTURE.md`), база пользователя со старой схемой открывается.
- [ ] Соединение SQLite — через `with store.conn()`.

## 6. Тесты
- [ ] Исправление бага приходит с тестом, который падал до исправления.
- [ ] Новая возможность — тест API на подставном Telegram (`tests/`); изменение редактора — проверка в `tests/e2e/` новым файлом.

## 7. Документация
- [ ] `summary=`, docstring и описания полей маршрута или инструмента MCP — на русском и понятны агенту без чтения кода.

## 8. Размер изменения
- [ ] Рефакторинг и новая возможность — разные PR.
- [ ] Дифф читается за 15 минут; больше — разбить.

## 9. Несколько агентов параллельно
- [ ] Дифф не выходит за пути, объявленные в задаче; если вышел, PR говорит почему.
- [ ] Ревью делает не автор: отдельный агент с этим списком. PR, которые трогают `security.py`, `api/raw.py`, `services/media.py`, `render.js`, `Dockerfile` или CI, дополнительно смотрит ревьюер безопасности.
- [ ] Ревьюер читает код и проверяет риски диффа: что новые тесты падают на коде без исправления, и свои пробы на опасных входах. Прогоны, которые прошёл зелёный CI, он не повторяет.

# Редактор (app/static/js)

- ES-модули без сборки, вход `main.js`, грузится как есть из `index.html`. Внешние библиотеки только вендорятся в `app/static/vendor/`.
- Общее состояние в `state.js`. Содержимое поста лежит в `S`: меняя его, вызывай `changed()` из `editor.js`, он обновляет предпросмотр, валидацию, автосохранение и историю отмены. Состояние страницы (`dirty`, `saveState`, `dark`, `canUndo`/`canRedo` в `history.js`) — это signals из `vendor/signals-core.js`: присвой `.value`, а DOM обновят эффекты в `bindEffects()` (`main.js`). Новое такое состояние заводи signal'ом, а не ручным обновлением DOM в нескольких местах.
- Отмена (`history.js`): снимок всего поста после паузы в правке. Новый черновик или открытый пост начинают историю заново (`resetHistory()`).
- Все запросы к серверу через `api()` из `api.js`; `fetch` в остальных модулях запрещён ESLint.
- DOM строится через `h()` из `dom.js`. `innerHTML`, `outerHTML`, `insertAdjacentHTML` запрещены (ESLint).
- `render.js` и `snippets.js` — классические скрипты, доступны как `window.RichRender` и `SNIPPETS`; `render.js` используется и на странице `/render`, поэтому не зависит от редактора.
- Подписи блоков и полей в `labels.js`; если подписи нет, редактор показывает имя из спецификации, это нормально.
- Типы проверяет `tsc --checkJs` по JSDoc, без сборки (`tsconfig.json`). Ответы API и состояние `S` описаны в `types/studio.d.ts` (в корне, чтобы не раздаваться как статика); поменял ответ сервера или поле `S` — поправь там. Содержимое поста (блоки, поля) нарочно не типизировано: его поля приходят из спецификации.
- После изменения: `npx eslint .`, `npx tsc -p .`, `npm run test:render`, для заметных изменений UI — `make e2e`.

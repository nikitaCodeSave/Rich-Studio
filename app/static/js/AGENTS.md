# Редактор (app/static/js)

- ES-модули, вход `main.js`, `index.html` грузит их как есть. Внешние библиотеки только вендорятся в `app/static/vendor/`.
- Содержимое поста лежит в `S` (`state.js`): меняя его, вызывай `changed()` из `editor.js`, он обновляет предпросмотр, валидацию, автосохранение и историю отмены. Состояние страницы (`dirty`, `saveState`, `dark`, `canUndo`/`canRedo` в `history.js`) — signals из `vendor/signals-core.js`: присвой `.value`, а DOM обновят эффекты в `bindEffects()` (`main.js`). Новое такое состояние заводи signal'ом, а не ручным обновлением DOM в нескольких местах.
- Новый черновик или открытый пост начинает историю отмены заново: `resetHistory()` из `history.js`.
- Запросы к серверу только через `api()` из `api.js`: `fetch` в остальных модулях запрещает ESLint.
- Новая самостоятельная часть интерфейса — компонент Lit в `components/` (`rs-*`, Lit вендорен в `vendor/lit-core.min.js`): свойства на вход, события наружу, состояние поста напрямую не трогает. В шаблон Lit идут только узлы из `RichRender` или текст (Lit экранирует его сам); `unsafeHTML` не используй.
- `<rs-preview>` держит пост в shadow root: стили `tg.css` и KaTeX действуют только внутри, `app.css` туда не попадает. В тестах содержимое ищи через `shadowRoot` (локаторы Playwright проходят в него сами).
- Вкладки HTML, Markdown и JSON — CodeMirror поверх textarea (`code-editor.js`). Значение остаётся в textarea: CodeMirror пишет в неё каждую правку с событием `input`, поэтому читай её и слушай её `input`. Текст снаружи — через `setSource(ta, text)`, вставка у курсора — `insertAtCursor` из `code.js`: прямое `ta.value = …` CodeMirror не увидит. CodeMirror импортируется только из `../vendor/codemirror.js` (путь к каталогу с хешем знает только он, его пишет `make vendor`), лениво и с запасным вариантом на textarea.
- Подсказки (`completion.js`) берут только данные из `/api/spec` (`types` с `const_field`, конверт поста `post`) и `snippets.js`: имён полей Bot API в JS нет. Новая подсказка — сначала случай в `tests/completion_unit.mjs`.
- `render.js` и `snippets.js` — классические скрипты, доступны как `window.RichRender` и `SNIPPETS`; `render.js` работает и на странице `/render`, поэтому не зависит от редактора.
- Таблица «В HTML» (`BLOCK_FIELDS`, `INLINE_FIELDS` в `html-export.js`): поле, которого в ней нет, даёт отказ, а не пропадает. Тип, который в HTML не записать, стоит в таблице с `null`, а причина отказа лежит в `NO_HTML`.
- Типы проверяет `tsc --checkJs` по JSDoc, без сборки (`tsconfig.json`). Ответы API и состояние `S` описаны в `types/studio.d.ts` (в корне, чтобы не раздаваться как статика): поменял ответ сервера или поле `S` — поправь там. Содержимое поста (блоки, поля) нарочно не типизировано: его поля приходят из спецификации.

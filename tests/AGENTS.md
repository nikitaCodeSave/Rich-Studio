# Тесты

- `pytest` идёт на подставном Telegram (`mock_telegram.py`), у каждого теста своя пустая папка данных, фоновые циклы выключены (`STUDIO_BACKGROUND=off`). Нужен цикл — вызови `scheduler.run_due_posts()` или `updates.handle_update()` сам.
- Тест чистой проверки (только `spec`, без студии и её данных) помечай `no_db` (на весь файл — `pytestmark = pytest.mark.no_db`, как в `test_rich_limits.py`): создание базы — почти всё время такого теста. Тест того же файла с фикстурой `client` базу получает всё равно.
- Подменять Telegram: `monkeypatch.setattr(telegram, "call", fake)`. Настройки: `monkeypatch.setattr(settings.get(), "preview_chat", "")`.
- Найденный баг — сначала падающий тест (`test_regressions.py`), потом исправление.
- `completion_unit.mjs` и `html_export.mjs` берут спецификацию у Python студии: `PYTHON=…`, `.venv` или `python3` с `requirements.txt`.
- `html_export.mjs` (`npm run test:export`): «В HTML» на блоках, которые настоящий Telegram сделал из каждого примера `telegram_parse/captured.json`, на посте со всеми типами спецификации и на отказах. Новый тип в спецификации: добавь его в пост `every` в этом файле.
- `preview_shots.mjs` (`npm run test:shots`): каждый пример из `examples/` в светлой и тёмной теме, проверка вёрстки (нет ошибок, у блоков есть размер, ничего не вылезает из пузыря) и скриншоты в `test-results/preview/`. Пиксели не сравниваются: шрифты на разных машинах разные. Новый блок в спецификации: добавь пример в `examples/` — HTML, JSON со списком блоков или JSON с `rich_message` целиком (с `media`); файлы `upload:<имя>` берутся из `examples/media/`.
- Браузерные проверки (`e2e_ui.mjs`) запускает `make e2e-local`: подставной Telegram и студия с пустым `DATA_DIR` на портах 7499 и 8099. `e2e/harness.mjs` не начинает, если студия по `BASE` ходит не в подставной Telegram: рабочая студия на 7424 опубликовала бы проверки в канал.
  - Проверка — отдельный файл `e2e/NN-имя.mjs` (`export default async function (ctx)`, помощники в `e2e/harness.mjs`); файлы идут по порядку имён на одной странице. Новая проверка — новый файл со следующим номером. Одна проверка: `make e2e-local ONLY=poll`.
  - Общая страница держит вкладки исходника в «Простом редакторе» (`page.fill` пишет в textarea); CodeMirror проверяется на своей странице в `e2e/43-code-editor.mjs`.
  - Жди событие, а не фиксированную паузу: `waitForFunction` для страницы (`e2e/19-a-new-post-becomes.mjs`), `until(() => …)` из `e2e/harness.mjs` для лога mock и API, считая от числа вызовов до действия: лог хранит всю сессию (`e2e/31-a-poll-goes-right.mjs`). Два действия, которые перезагружают один список (вкладка, затем фильтр), идут друг за другом: дождись результата первого, иначе старая перезагрузка может прийти последней.
  - Что проверка ждёт событие, доказывает `E2E_SLOW=500 make e2e-local ONLY=<проверка>`: каждый запрос страницы задерживается, и проверка с паузой падает.
